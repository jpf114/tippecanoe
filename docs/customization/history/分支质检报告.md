### 2.2 严重问题（全部经代码验证）

**CK-S1【dir 模式 resume 后 metadata 永久错误】**（运行时实锤）
dirtiles.cpp:294-297：dir_write_metadata 沿用上游 --allow-existing 语义——metadata.json 已存在时**静默跳过写入**。时序：SIGTERM 部分完成时先写了 maxzoom 缩小的 metadata → resume 完成后发现文件已存在直接返回 → **metadata 永久停留在中断时刻**（maxzoom/center/strategies/tippecanoe_decisions/vector_layers 全错，z8 瓦片存在但对客户端不可见）。空跑 resume 也无法修复。mbtiles 模式因 INSERT OR REPLACE 幂等覆盖而不受影响。
**修复**：resume 分支调用 dir_write_metadata 时强制覆盖（加 force 参数，或先 unlink 旧 metadata.json）。

**CK-S2【首 zoom 中途中断后 resume 必崩】**（代码确认，kill -9/断电场景）
checkpoint.cpp:2333：cleanup_resume_tiles 在 last_completed_zoom < 0 时直接 return，不清理 map 表；而 mbtiles.cpp:72 建了 {zoom_level,tile_column,tile_row} 唯一索引、:130 用普通 insert。当作业在 entry 快照完成后、首个 zoom 提交前被 kill -9/断电（恰是 checkpoint 要防的核心场景），map 表已有部分 z=iz 瓦片 → resume 重写 → 唯一索引冲突 → exit(EXIT_SQLITE)，checkpoint 变相报废。
**修复**：last_completed_zoom < 0 且 map 表非空时也执行清理（删除 zoom_level >= iz 的行）。

**CK-S3【resume + prefilter/postfilter 越界读（UB）】**（代码确认，条件性）
resume 恢复时 pool_off/initial_x/initial_y 只按 CPUS 个元素分配（main.cpp:1231-1239），而 prefilter/postfilter 输出的 feature 的 segment 被写成 tiling_seg = thread + layermaps_off（plugin.cpp:245，≥ 2*CPUS）；下一 zoom 反序列化时 pool_off[sf.segment]（serial.cpp 1135 一带）越界读。普通 resume（无 filter）segment ∈ [0,CPUS) 安全——与实测一致。另外 fingerprint 含 cpus 但 open_resume 不校验：跨机续跑且 CPUS 变小时同样越界。
**修复**：按 2*CPUS（且以 state.cpus 为准）保存/分配三数组，resume 时校验 cpus 一致。

**CK-S4【自包含 resume 未恢复 tiling 参数】**（运行时实锤）
裸 --resume 设计为自包含，但 gamma、buffer、droprate、simplification、full/low/min detail、prefilter/postfilter、attribute_accum、json filter 等影响切片行为的参数全部取**当前进程默认值**；实测携带 -z7 -Z0 resume 与原作业不同参数时静默忽略、无警告。续跑 zoom 的切片行为可能与原作业不一致。
**修复**：把上述参数持久化进 state.json 并在 resume 时恢复；或至少与 normalized_cmd 比对，不一致时报 fingerprint mismatch。

**CK-S5【skip_children/strategies/layermaps 无 fsync、无 CRC】**（代码确认）
write_skip_children_blob（checkpoint.cpp:840-857）仅 fwrite+fclose；读取端 read_skip_children_blob（859-877）fread 返回值不检查。断电后这些 blob 内容可为空/截断：空 → skip_children 静默丢失；截断 → 垃圾数据插入集合。两者都导致 resume 后输出错误瓦片且无任何告警。geom 链路有 fsync+CRC，三类辅助 blob 两者皆无——持久化强度不对称。
**修复**：写入后 fsync + 追加 CRC（复用 geom 链路机制）；读取端检查 fread 返回值与文件大小。

**CK-S6【输出侧 synchronous=0 与 checkpoint 强度不匹配】**（架构级）
mbtiles 输出沿用上游 synchronous=OFF：断电时 page cache 丢失，可能出现 state.json 已提交 zoom N 而输出库缺瓦片的状态脱节。checkpoint 场景打破了上游"整体失败就整体重跑"的前提。
**修复**：checkpoint 模式下将 mbtiles 设为 synchronous=NORMAL（或 resume 起点前对已完成 zoom 做抽样校验）。

**CK-S7【TEMP_FILES/CPUS 不校验】**
restore_tiling 按当前进程探测的 TEMP_FILES（受运行时 fd 限制影响）加载 blob，不与 state_.temp_files 比对。原作业 24 文件、续跑环境 16 文件时**静默丢数据**。
**修复**：restore_tiling 开头校验 TEMP_FILES/CPUS 与 state 一致，不一致报错退出。

### 3.2 严重问题（全部经代码验证，标注实测状态）

**DB-S1【ctid 分片死代码 → auto 模式永远单线程】**（实测实锤）
build_sharded_query 把分片条件包成 SELECT * FROM (base_query) AS _shard_src WHERE abs(hashtext(ctid::text))...——子查询结果没有 ctid 列，probe 必然报错 → fallback 顺序读。文档宣称的自动并行从不生效，用户必须显式给 shard_key。**这是 db 分支的核心卖点失效。**
**修复**：把 ctid 条件推入内层查询（FROM table 层级），或改用基于主键/序号列的方案。

**DB-S2【range 分片对非整数 key 静默丢行】**
min/max 用 CAST(key AS bigint) 取整，条件 key >= start AND key < end 用原始 key：numeric key=1.5 在 min=2 时被排除，**该行不属于任何线程 → 数据丢失**。整数 key 无问题。
**修复**：range 边界用与条件一致的原始类型（numeric），或仅在 key 为整数类型时启用 range 分片。

**DB-S3【-s/--projection 与硬编码 ST_Transform 无冲突校验】**
maindb.cpp:2475 接受任意投影参数；postgis.cpp:899/915 恒定 ST_AsBinary(ST_Transform(geom,4326))，wkb_parser 按 4326 加坐标。用户指定非 4326 投影时静默产出错误结果。
**修复**：PostGIS 输入下禁止/警告 -s，或把投影下推到 SQL（ST_Transform 到目标 SRID）。

**DB-S4【GEOMETRYCOLLECTION 静默丢数据】**（实测实锤）
wkb_parser 将 collection 所有子几何坐标摊平进同一 drawvec 并标 GEOM_TYPES → postgis.cpp 映射为 MULTIPOLYGON 序列化；实测混合 collection 的 feature **完全不出现在瓦片中且无任何 parse error**。原版 GeoJSON 路径会把 collection 拆成多个 feature。
**修复**：对 collection 逐子几何生成独立 feature（对齐原版语义）；至少 parse error 计数 + 告警。

**DB-S5【E11000 重复键不分类 → 合法重跑"伪丢弃"+非零退出】**（实测实锤）
flush_batch_with_retry 对所有异常统一 attempts++; total_errors++; 重试。E11000（数据已在库）应视为幂等成功，却被重试 3 轮后整批丢弃，1154 瓦片全"失败"，exit 121。此外 total_errors 把重试成功也计数：单次瞬时网络抖动恢复后仍 exit EXIT_MONGO。
**修复**：按错误码分类——E11000 幂等成功（或走 upsert）；瞬时网络错误重试不计入 fatal；仅持久错误计入退出码判定。

**DB-S6【mongodb+srv:// 被静默破坏】**
parse 接受 mongodb+srv://，但 uri() 从组件重建为 mongodb://host:port——SRV 记录不被解析，Atlas 用户必然连接失败。
**修复**：SRV 输入原样透传给驱动，不做重建。

**DB-S7【游标失败 fallback 全量 PQexec → 大表 OOM】**
run_standard_query_mode（postgis.cpp:1399-1420）一次性物化全部行（WKB hex 文本 2× 膨胀，服务端+客户端双份）。use_cursor=false、count≤batch_size、BEGIN/DECLARE 失败三条路径都走它。
**修复**：fallback 改为分批 LIMIT/OFFSET 或服务端游标重试；设置行数/内存上限。

**DB-S8【SRID 只采样首行】**
SELECT ST_SRID(geom) ... LIMIT 1：空表得 srid=0 → 走 ST_Transform(geom,4326) 分支直接整表失败；混合 SRID 表首行为 4326 时静默跳过变换。
**修复**：采样 SELECT DISTINCT ST_SRID(geom) ... LIMIT 2，多值/0 值明确报错。

**DB-S9【无断线重连，重试函数是死代码】**
execute_query_with_retry（postgis.cpp:1247）定义后无调用；FETCH 失败仅 break；事务 aborted 后 close_cursor_tx 静默失败。
**修复**：接入重试函数或删除死代码；FETCH 失败至少输出明确错误。

**DB-S10【hash 分片：abs(hashtext) 溢出 + N 倍全表扫描】**
hashtext 恰为 INT_MIN 时 PG 报 "integer out of range"，整个分片查询失败（概率 2^-32）；且每线程全表扫描计算哈希、无法用索引，总 IO ≈ N×表。
**修复**：用 mod(hashtext(...), n) 规避溢出；hash 分片改用主键范围抽样或物化分片键。

**DB-S11【各线程快照不一致】**
每线程独立 BEGIN ISOLATION LEVEL REPEATABLE READ（postgis.cpp:1430-1447），probe 与查询不在同一事务：并发写表时行可能重复/丢失。
**修复**：主线程 BEGIN; SELECT pg_export_snapshot(); 各线程 SET TRANSACTION SNAPSHOT 共享快照。
