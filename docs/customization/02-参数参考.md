# 02 参数参考（tippecanoe-db）

> 范围：`tippecanoe-db` 相对上游 `tippecanoe` 新增/差异的全部选项。
> 与上游一致的通用瓦片选项（`-z/-Z`、简化、投影、属性过滤等）不在本文范围，
> 且两者由 [options_table.hpp](../../options_table.hpp) 单一来源自动同步——
> 新增通用选项后两入口 getopt/help 自动一致，无需双表维护。
> 实时清单：`./tippecanoe-db --help` 与 `./tippecanoe-db --help-advanced`。

## 1. 三种输出模式

由 [db_options.hpp](../../db_options.hpp) `db_output_mode` 判定：

| 模式 | 触发组合 | 行为 |
|---|---|---|
| 双输出（默认业务形态） | `--mongo` + (`-o` 或 `--output-to-directory`) | Mongo 为业务输出；本地瓦片为校验输出，每瓦片先 Mongo 后本地（锁外），zoom 回滚先本地后 Mongo |
| 仅本地 | 无 `--mongo`，有 `-o` / 目录输出 | 不连 Mongo，等同普通 tippecanoe 流程 + PostGIS 输入 |
| 仅业务 | 仅 `--mongo`，无本地输出 | 只写 Mongo |

## 2. PostGIS 输入选项（16 项）

| 选项 | 参数 | 默认 | 说明 |
|---|---|---|---|
| `--postgis=<URI>` | 连接串 | 必填（与 `--postgis-sql` 二选一组合） | `postgresql://[user[:password]@]host[:port]/dbname`；也支持分项（见 §4） |
| `--postgis-table=<表名>` | 表名 | 与 `--postgis-sql` 二选一 | 表模式读取 |
| `--postgis-sql=<SQL>` | SQL | - | 子查询模式：`(SELECT ...) AS _subq`；大表无分片键时拒绝非 cursor 全量物化（OOM 防护，见 03 架构 §4.3） |
| `--postgis-geometry-field=<列>` | 列名 | 自动推断 | 几何列名非默认（`geom`/`geometry`/`the_geom` 等）或无法推断时必填 |
| `--postgis-columns=<a,b,c>` | 列表 | 全部非几何列 | 仅投影指定属性列 |
| `--postgis-columns-best-effort` | 开关 | 关 | 指定列不存在时跳过而非报错 |
| `--postgis-canonical-attr-order` | 开关 | **默认开** | 属性按 to_jsonb 键序（键长+字典序）规范化输出 |
| `--postgis-no-canonical-attr-order` | 开关 | - | 关闭规范化（保留 PG 侧投影顺序） |
| `--postgis-profile` | 开关 | 关 | 输出读取/解析各阶段计时 |
| `--postgis-shard-key=<列>` | 列名 | 无（游标模式） | 并行分片键；hash 取模或 range 分片（见 §5） |
| `--postgis-shard-mode=<mode>` | `hash`/`range` | `hash`（未指定时自动） | 分片策略；`range` 按键值均分区间 |
| `--postgis-progress-count` | 开关 | 关 | 按计数输出进度 |

**读取行为默认值**（[config.hpp](../../config.hpp)）：

| 项 | 默认值 | 修改方式 |
|---|---|---|
| 并行读取线程数 | 可用 CPU 数（本机实测 4） | 环境变量 `TIPPECANOE_MAX_THREADS=<n>`；上限 50（`MAX_POSTGRES_CONNECTIONS`，超出自动钳制） |
| cursor 批大小 `batch_size` | 1000 | 无 CLI 入口（编译期常量 `DEFAULT_POSTGIS_BATCH_SIZE`，见 [config.hpp](../../config.hpp)；允许范围 100–10000） |
| cursor 模式 | 开（>1000 行自动启用） | 行数 ≤ batch 或显式关闭时退化为单批物化 |
| 连接超时 | 30s | `POSTGIS_CONNECTION_TIMEOUT_SEC` |
| 失败重试 | 3 次 | `MAX_POSTGIS_RETRIES` |
| bytea 传输格式 | 会话级 `SET bytea_output = hex` | 固定（escape 八进制仅作解码兜底） |

## 3. MongoDB 输出选项（17 项）

| 选项 | 参数 | 默认 | 说明 |
|---|---|---|---|
| `--mongo=<URI>` | 连接串 | - | `mongodb://[user:password@]host[:port]/dbname?collection=name[&authSource=src]` |
| `--mongo-host/-port/-dbname/-collection/-username/-password/-auth-source` | 分项 | 同 URI 二选一风格 | 分项提供连接要素，见 §4 |
| `--mongo-batch-size=<n>` | 数值 | 自动分档 | 手动固定写批量；范围 10–1000 |
| `--mongo-pool-size=<n>` | 数值 | 10（上限 50） | 连接池大小 |
| `--mongo-timeout=<ms>` | 毫秒 | 30000 | 操作超时 |
| `--mongo-no-indexes` | 开关 | 默认建索引 | 跳过瓦片坐标唯一索引（唯一索引是 E11000 重复键防护的载体） |
| `--mongo-drop-collection` | 开关 | 关 | 启动时删除集合 |
| `--mongo-metadata` / `--mongo-no-metadata` | 开关 | 不写元数据 | 是否写元数据文档 |
| `--mongo-fail-on-discard` / `--mongo-no-fail-on-discard` | 开关 | 默认 fail | 批量写入被丢弃（如重复键）时的失败策略 |

**自动批量分档**（按当批瓦片数据量，[config.hpp](../../config.hpp)）：

| 数据量阈值 | 批大小 |
|---|---|
| < 10,000 | 100（默认） |
| ≥ 10,000 | 200 |
| ≥ 100,000 | 500 |
| ≥ 500,000 | 800 |
| ≥ 2,000,000 | 1000 |

## 4. 连接串与分项的优先级

`--postgis`/`--mongo` 单串提供全部信息时，分项选项可省略；两者可混用
（单串缺的要素由分项补齐，如单串无密码时用 `--postgis-password`）。
分项等价形式：

```bash
tippecanoe-db --postgis-host 127.0.0.1 --postgis-port 5432 \
  --postgis-dbname TippTest --postgis-user postgres --postgis-password postgres \
  --postgis-table china --postgis-geometry-field geom -o out.mbtiles
```

## 5. 并行读取与分片

- 未指定 `--postgis-shard-key`：4 类默认（CPU 数）线程各自持有独立连接与
  `SCROLL CURSOR`，`FETCH FORWARD 1000` 分批，每批在多线程间再均衡。
- 指定 `--postgis-shard-key`：
  - `hash`（默认）：`abs(hashtext(key)) % nthreads = thread_id`，PostgreSQL 服务器端过滤；
  - `range`：按 key 值域均分区间给各线程。
- 大表 + `--postgis-sql` 无分片键时，非 cursor 全量物化会被拒绝（防 OOM），
  按提示改用 cursor 模式（默认）或加 `--postgis-shard-key`。

## 6. 上游不存在的退出码（tippecanoe-db 新增语义）

| 退出码 | 含义 |
|---|---|
| 121 | checkpoint 数据校验失败或磁盘空间不足（两入口共用） |
| 122 | MongoDB 写入/操作失败 |
| 110 | SIGTERM 于读入阶段直接终止（无快照，见 04-断点续做） |

完整退出码表见 [errors.hpp](../../errors.hpp)（100–122）。

## 7. 典型命令

```bash
# 双输出：PostGIS 读入 → Mongo 业务库 + mbtiles 校验（断点续做启用）
tippecanoe-db --checkpoint-dir=/data/ckpt/job1 \
  --postgis postgresql://postgres:pg@10.1.1.10:5432/gis --postgis-table big_merge \
  --postgis-geometry-field geom --postgis-shard-key id \
  --mongo "mongodb://admin:pass@10.1.1.20:27017/gis?collection=tiles&authSource=admin" \
  -o /data/out/verify.mbtiles -f -Z0 -z12

# 大表 SQL 模式（cursor 分批，属性列白名单）
tippecanoe-db -f -Z0 -z8 -o out.mbtiles \
  --postgis postgresql://... --postgis-sql "SELECT * FROM roads WHERE level > 3" \
  --postgis-geometry-field geom --postgis-columns id,name,level
```
