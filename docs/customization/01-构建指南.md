# 01 构建指南

> 目标：任何一台 x86_64 或 aarch64 的 Linux 机器，**无需网络、无需 vcpkg**，
> 仅凭仓库内容即可完成从三方库到全部二进制的构建。

## 1. 依赖总览

| 二进制 | 依赖来源 | 说明 |
|---|---|---|
| `tippecanoe` / `tippecanoe-decode` / `tile-join` / `tippecanoe-enumerate` / `tippecanoe-json-tool` / `tippecanoe-overzoom` | 系统库 | `-lm -lz -lsqlite3 -lpthread`（系统 zlib / sqlite3 开发包） |
| `tippecanoe-db` / `unit` | **vendor 静态库**（`third_party/_install/`） | PostgreSQL libpq、mongo-c-driver、mongo-cxx-driver，全部静态链入，产物无 .so 依赖 |
| 构建工具链 | 系统 | `gcc/g++`（vendor 模式要求 ≥ GCC 7，见 1.2 版本配对）、`cmake ≥ 3.15`、`make`、`perl`（PG configure 需要） |

## 2. vendor 三方库（tippecanoe-db 依赖）

### 2.1 版本与配对

| 库 | 版本 | 为什么是这个版本 |
|---|---|---|
| PostgreSQL | 18.0 | 只取 libpq 客户端；源码已裁剪至 libpq 构建所需（154M→31M），并保留 configure 校验标记文件（`src/backend/access/common/heaptuple.c`、`src/backend/port/`）与 libpgport/libpgcommon srv 对象所需的生成头 |
| mongo-c-driver | 1.29.0 | 与 mongocxx r4.0.0 官方配对（ABI 1.0）；SSL/KMS/SASL/zlib/snappy/zstd/ICU 全禁用 → 零外部依赖 |
| mongo-cxx-driver | r4.0.0 | 官方要求 c-driver 1.29.0；**r4.3+ 硬性要求 GCC 8.1+**，r4.0.0 支持 GCC 7（aarch64 离线机 gcc 7.3 实测通过）；API 兼容（v1 命名空间自 4.0 引入） |

> 注意：mongo-cxx-driver r4.5.3 需要 c-driver 2.3.3 且 GCC ≥ 8.1，在 GCC 7 环境不可用——
> 若未来构建机 GCC ≥ 8.1，可整体升级为 r4.5.3 + c-driver 2.3.3 组合（库文件名会变为
> `libmongocxx1-static.a` 等，需同步修改 Makefile 的 `DB_EXTRA_LIBS`）。

### 2.2 构建步骤

```bash
cd <仓库根>
./third_party/build_all.sh          # 产物安装到 third_party/_install/
# 可选：JOBS=8 ./third_party/build_all.sh 控制并行度
# 可选：./third_party/build_all.sh /path/to/prefix 指定安装目录

make all-db                         # 核心 6 二进制 + tippecanoe-db
make test                           # 全量回归（含 unit、checkpoint-test）
```

`build_all.sh` 依次执行：

1. **PostgreSQL**：`configure`（`--without-readline/zlib/openssl/icu/lz4/libxml/libxslt/gssapi --disable-rpath`）
   → `make -C src/interfaces/libpq NO_GENERATED_HEADERS=1` → 依次 install libpq / src/port / src/common，
   补拷 `postgres_ext.h`（libpq install 不含它，而 `make -C src/include install` 会牵入 backend 生成物）。
2. **mongo-c-driver 1.29.0**：树外构建（`third_party/build/mongoc`），全禁可选依赖，
   `-DCMAKE_INSTALL_LIBDIR=lib`（兼容 RHEL 系默认 lib64）。
3. **mongo-cxx-driver r4.0.0**：树外构建，`-DCMAKE_PREFIX_PATH` 指向第 2 步安装的
   cmake 包（**必须能 find_package 成功，否则会尝试联网 FetchContent 并失败**）、
   `-DMONGOCXX_ENABLE_SSL=OFF`、C++17。

### 2.3 安装布局（Makefile 的引用关系）

```
third_party/_install/
├── pg/
│   ├── include/{libpq-fe.h, postgres_ext.h, libpq-events.h, postgresql/...}
│   └── lib/{libpq.a, libpgport.a, libpgcommon_shlib.a, ...}
├── mongoc/
│   ├── include/{libmongoc-1.0/, libbson-1.0/}
│   └── lib/{libmongoc-static-1.0.a, libbson-static-1.0.a, cmake/...}
└── mongocxx/
    ├── include/{mongocxx/v_noabi/, bsoncxx/v_noabi/, mongocxx/, bsoncxx/}
    └── lib/{libmongocxx-static.a, libbsoncxx-static.a, cmake/...}
```

Makefile 检测 `third_party/_install/pg/lib/libpq.a` 存在即启用 vendor 模式
（include 布局与四个 `*_STATIC` 宏以各库 pkgconfig 的 Cflags 为准）。

### 2.4 离线编译要点（aarch64 实测：10.1.1.185, gcc 7.3.0 / cmake 3.16.5 / glibc 2.28）

- 整棵仓库（含 third_party 源码）rsync 到目标机后 `./third_party/build_all.sh && make all-db`
  即可，全程无网络访问。
- glibc < 2.34 时 `shm_open/shm_unlink` 在 librt——Makefile 的 `DB_EXTRA_LIBS` 已含 `-lrt`，
  新版 glibc 上该库为空壳，无副作用。
- PG 静态链接 libpq 的编码公开符号在 `libpgcommon_shlib.a`（`libpgcommon.a` 只导出
  `_private` 后缀版本，PG 18 为动态/静态链接区分的设计）——Makefile 已按此配置。

### 2.5 常见构建问题

| 现象 | 原因 | 处置 |
|---|---|---|
| `cannot find -lpgcommon` / `pg_char_to_encoding` 未定义 | unit 链接用了 `libpgcommon.a` | 已修复：Makefile 统一用 `-l:libpgcommon_shlib.a` |
| `cannot find libpgcommon_shlib.a`（mongocxx 段） | RHEL 系 cmake 默认装到 `lib64` | 已修复：build_all.sh 传 `-DCMAKE_INSTALL_LIBDIR=lib` |
| mongocxx configure 报 "Required MongoDB C Driver libraries not found" 后联网下载 | CMAKE_PREFIX_PATH 未指到 `_install/mongoc/lib/cmake` | 检查第 2 步是否成功安装（lib/cmake/ 下应有 mongoc-1.0、bson-1.0 包） |
| `make: *** uninstall.sh.d: Is a directory` | mongocxx uninstaller 把清单目录落在 CWD | build_all.sh 已做防御清理；手工删除该目录即可 |
| `GCC 8.1 or newer is required` | 误用了 mongocxx r4.3+ | 按本指南使用 r4.0.0 |

## 3. vcpkg 回退模式（legacy）

`third_party/_install/pg/lib/libpq.a` 不存在时，Makefile 自动回退 vcpkg：

```bash
git clone https://github.com/microsoft/vcpkg.git "$HOME/vcpkg"
"$HOME/vcpkg/bootstrap-vcpkg.sh"
"$HOME/vcpkg/vcpkg" install sqlite3 zlib libpq mongo-cxx-driver
make VCPKG_ROOT="$HOME/vcpkg" install-db   # 或 VCPKG_TRIPLET=x64-linux-dynamic
```

该模式仅作过渡兼容；新部署一律使用 vendor 模式。

## 4. 交付物形态

| 形态 | 命令 | 说明 |
|---|---|---|
| 动态（默认） | `make all-db` | 二进制只依赖系统 libc/libz/libsqlite3；vendor 三库静态链入 tippecanoe-db |
| 静态 | `make LDFLAGS=-static`（核心 6 个） | 核心二进制全静态；tippecanoe-db 因 vendor 库保持动态链接系统库 |
| 交叉/异构 | 在目标架构机器上执行 1-2 步 | 不做交叉编译（glibc 匹配优先），实测 aarch64 现场编译 ~15 分钟 |
