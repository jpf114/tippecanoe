# Tippecanoe 断点续做（Checkpoint / Resume）

本文档说明原生 `tippecanoe`（GeoJSON / CSV 等读入路径）的 **zoom 级断点续做** 功能。
**不包含** `tippecanoe-db`（PostGIS / Mongo 等），后者在后续版本中再考虑。

---

## 1. 功能概述

在生成矢量瓦片时，任务往往耗时很长（读入大 GeoJSON、多级 zoom 切片）。进程被 `kill -9`、OOM 或机器重启打断后，传统做法只能从头重跑。

断点续做提供：

- **专用 checkpoint 工作目录**（与 `-o` / `-e` 输出路径分开）；
- **每个 zoom 成功结束后** 落盘中间状态；
- **`--resume`** 时跳过读入与 radix，从「上一完成 zoom 的下一级」继续切片。

### 1.1 两阶段模型（必读）

| 阶段 | 内容 | 是否 checkpoint |
|------|------|-----------------|
| **阶段 A** | 读入 GeoJSON、radix 排序、合并 stringpool、建 shared_nodes 等 | **否** |
| **阶段 B** | `traverse_zooms`：按 zoom 写 mbtiles 或目录瓦片 | **是**（每 zoom 一次） |

因此：

- 中断发生在 **读入 / 排序** 时：checkpoint 目录里通常还没有可用的「切片入口快照」，下次只能 **全量重跑**（与计划一致）。
- 中断发生在 **切片过程中**：已完成的 zoom 有记录，且已保存进入下一 zoom 所需的 geom 分片与 stringpool，可 **`--resume` 续跑**。

「zoom 级」**不是**「只记录 mbtiles 里已有哪些 z」，而是必须保存 **算法中间态**（否则无法从 z+1 继续，因为 z+1 的输入来自 z 结束时生成的 geom 分片，且属性索引依赖同一次读入的 stringpool）。

### 1.2 核心流程图解

#### 首次运行（启用 checkpoint）

```
                          ┌──────────────────────────────────────────────────────┐
                          │                    阶段 A: 读入与排序                  │
                          │                                                      │
  输入文件 ──────────────►│  读入 GeoJSON → radix 排序 → 合并 stringpool          │
  (china.geojson)        │  → 建 shared_nodes/bloom → 计算 maxzoom/basezoom     │
                          └──────────────┬───────────────────────────────────────┘
                                         │
                                         ▼
                          ┌──────────────────────────────────────────────────────┐
                          │           snapshot_tiling_entry (一次性)              │
                          │                                                      │
                          │  保存: stringpool, geom.0, shared_nodes, bloom,      │
                          │        pool_off, initial_x/y, layermaps               │
                          │  staging/ ──rename──► blobs/                          │
                          │  SQLite: INSERT tiling_state (entry_snapshot_done=1)  │
                          └──────────────┬───────────────────────────────────────┘
                                         │
                                         ▼
                          ┌──────────────────────────────────────────────────────┐
                          │              阶段 B: traverse_zooms                  │
                          │                                                      │
                          │  for z = iz .. maxzoom:                              │
                          │    ┌───────────────────────────────────────────┐     │
                          │    │  读取 geomfd[j] → 切分/合并/写瓦片          │     │
                          │    │  → 生成 subfd[j] (下一级输入)               │     │
                          │    │  → geomfd[j] = subfd[j]                    │     │
                          │    └──────────────┬────────────────────────────┘     │
                          │                   │                                  │
                          │           err == INT_MAX ?                          │
                          │           ┌─── 是 ───┐                              │
                          │           ▼          │                              │
                          │    on_zoom_complete() │                              │
                          │    ┌──────────────────────────────────────────┐      │
                          │    │ 1. 写 geom/skip_children/strategies     │      │
                          │    │    → staging/                            │      │
                          │    │ 2. rename staging/ → blobs/ (原子)       │      │
                          │    │    无新数据的 slot: unlink 旧 blob       │      │
                          │    │ 3. SQLite 事务:                          │      │
                          │    │    INSERT zoom_commit (zoom, committed)  │      │
                          │    │    UPDATE tiling_state                   │      │
                          │    │       SET last_completed_zoom = z       │      │
                          │    └──────────────────────────────────────────┘      │
                          │           │          │                              │
                          │           ▼          ▼                              │
                          │      z < maxzoom   z == maxzoom                    │

                          └──────────────────────────────────────────────────────┘
```

#### 断点续跑（`--resume`）

```

                          │  ├── 校验 fingerprint (SHA-256)                      │
                          │  ├── 读取 tiling_state: last_completed_zoom          │
                          │  └── 计算 resume_iz = last_completed_zoom + 1        │
                          └──────────────┬───────────────────────────────────────┘
                                         │
                                         ▼
                          ┌──────────────────────────────────────────────────────┐
                          │           restore_tiling()                           │
                          │                                                      │
                          │  mmap(stringpool)  ← blobs/stringpool                │
                          │  open(geom.N)      ← blobs/geom.0..N-1              │
                          │  read(pool_off)    ← blobs/pool_off.bin             │
                          │  read(initial_x/y) ← blobs/initial_x/y.bin          │
                          │  read(layermaps)   ← blobs/layermaps.bin            │
                          │  mmap(shared_nodes)← blobs/shared_nodes             │
                          │  read(bloom)       ← blobs/shared_nodes.bloom       │
                          │  read(skip_children)← blobs/skip_children.bin        │
                          │  read(strategies)  ← blobs/strategies.bin           │
                          └──────────────┬───────────────────────────────────────┘
                                         │
                                         ▼
                          ┌──────────────────────────────────────────────────────┐
                          │  traverse_zooms(iz = last_completed_zoom + 1)        │
                          │                                                      │
                          │  跳过阶段 A，直接从断点 zoom 继续切片                    │
                          │  后续流程与首次运行阶段 B 完全一致                       │
                          └──────────────────────────────────────────────────────┘
```

## 2. 设计原理

### 2.1 核心架构：SQLite 账本 + 文件系统仓库

| 内容 | 存储位置 | 原因 |
|------|----------|------|
| 作业指纹、命令行、zoom 进度、时间戳 | `state.sqlite` | 便于事务、查询、原子更新 |
| stringpool、geom 分片、shared_nodes、bloom | `blobs/` 下普通文件 | 可达 GB 级；SQLite BLOB 性能差、单文件易膨胀 |
| 写入中的数据 | `staging/` | 写完后 `rename` 到 `blobs/`，再更新 SQLite |

SQLite 充当 **作业账本**；文件系统充当 **中间态仓库**。

**技术选型依据**：

- **SQLite（WAL 模式）**：元数据量小（KB 级），需要事务保证（fingerprint + zoom_commit 的原子性），WAL 模式支持并发读取；
- **文件系统（blobs/）**：中间态数据量大（GB 级），使用 `mmap` 直接映射到进程地址空间，避免额外的序列化/反序列化开销；
- **staging → blobs 原子提交**：`rename()` 在同一文件系统上是原子操作，保证 `kill -9` 后 `blobs/` 中始终存在有效的完整版本。

### 2.2 原子提交顺序（防止半截状态）

每个 zoom 的 `commit` 顺序为：

1. 将新的 geom 分片、`skip_children`、`strategies` 写入 `staging/`；
2. 对相关文件 `fsync`；
3. **原子 `rename`** `staging/` → `blobs/`：
   - 有新数据的文件：`rename()` 原子替换旧版本；
   - 无新数据的 slot：`unlink` 删除旧 blob（防止读到过期数据）；
4. SQLite 事务：写入 `zoom_commit`，更新 `tiling_state.last_completed_zoom` 等。

**关键设计**：步骤 3 中 **不先删除旧 blob 再 rename**，而是直接 `rename` 覆盖。若先删后写，在 `kill -9` 后 `blobs/` 中可能为空，导致 resume 失败。`rename()` 原子替换保证 `blobs/` 中始终存在有效版本。

仅在当前 zoom 的 drop 多 pass 循环 **全部成功**（`again == false`）且 `err == INT_MAX` 时调用 `on_zoom_complete`，避免「重试中」的错误进度。

### 2.3 与切片算法的关系

- **不修改** `write_tile`、drop/coalesce、几何切分、radix 等核心逻辑；
- 仅在 `traverse_zooms` 循环末尾增加 **一处** 钩子，具体逻辑在 `checkpoint.cpp`；
- `main.cpp` 的 `read_input` 首尾负责「是否跳过读入」与 `snapshot_tiling_entry`。

### 2.4 作业指纹（fingerprint）

续跑前会计算 SHA-256 指纹，与首次运行时写入 `state.sqlite` 中 `job.fingerprint` 的值比对。参与哈希的包括：

- 格式版本 `TIPPECANOE_CHECKPOINT_FORMAT`（当前为 `1`）；
- **规范化后的命令行**（已剔除 `--checkpoint-dir` 及其参数、`--resume` 及其参数、`--checkpoint-force`、`-F`、`-f` 等与瓦片内容无关或仅影响输出的标志）；
- 输出模式（`mbtiles` / `directory` / 记录用 `pmtiles`）与 **输出路径绝对路径**；
- `TEMP_FILES`、`CPUS`；
- `prevent[]` / `additional[]` 标志位；
- 输入文件列表：`绝对路径 + size + mtime`（排序后）。

**命令行规范化规则**：

| 标志 | 处理方式 | 说明 |
|------|----------|------|
| `--checkpoint-dir=DIR` | 整体移除 | 等号形式，标志含参数 |
| `--checkpoint-dir DIR` | 标志和参数均移除 | 空格形式，需跳过下一个 token |
| `--resume=DIR` | 整体移除 | 等号形式 |
| `--resume DIR` | 标志和参数均移除 | 空格形式 |
| `--checkpoint-force` | 移除 | 无参数标志 |
| `-F` / `--allow-existing` | 移除 | 无参数标志 |
| `-f` / `--force` | 移除 | 无参数标志 |

**任一影响瓦片内容的参数或输入文件变化**，续跑会以退出码 `101`（`EXIT_ARGS`）失败并打印 stored / expected 指纹。

续跑时仍须在命令行传入输入文件路径，用于校验；**不会**再执行读入与 radix（当存在有效切片 checkpoint 时）。

### 2.5 关键算法逻辑

#### 2.5.1 `copy_fd_to_file` — fd 到文件的安全拷贝

`on_zoom_complete` 需要将 `geomfd[j]` 的内容拷贝到 `blobs/geom.j`。由于 `geomfd[j]` 同时被 `traverse_zooms` 后续代码使用（`fdopen(geomfd[j], "rb")` 读取），拷贝过程必须 **保存并恢复文件偏移量**：

```
saved_pos = lseek(fd, SEEK_CUR)     // 保存当前偏移量
lseek(fd, 0, SEEK_SET)              // 回到文件头
read(fd, ...) → write(dest, ...)   // 拷贝数据
lseek(fd, saved_pos, SEEK_SET)      // 恢复原始偏移量
```

若不恢复偏移量，`read()` 会将 fd 偏移量推到文件末尾，导致后续 `fdopen()` 读不到任何数据。

#### 2.5.2 `compressed` 标志的正确计算

在 `traverse_zooms` 中，z0 的数据是未压缩的（排序和 maxzoom 修正需要操作原始数据），z1+ 的数据是压缩的。resume 时从 `last_completed_zoom + 1` 开始，该 zoom 的输入来自上一级 `on_zoom_complete` 保存的压缩数据，因此：

```
compressed = (z > 0)    // z0 未压缩，z1+ 均为压缩
```

注意：不能使用 `compressed = (z != iz)`，因为当 `iz > 0`（resume 起始 zoom）时，`z == iz` 会导致 `compressed = false`，从而错误地按未压缩格式读取压缩数据。

#### 2.5.3 `skip_children` / `strategies` 的容错读取

`read_skip_children_blob` 和 `read_strategies_blob` 在文件不存在时 **优雅返回**（空集合），而非 `exit(EXIT_OPEN)`。原因：若进程在第一个 zoom 完成前被 `kill -9`，`blobs/` 中尚无这两个文件，但 `stringpool` 和 `geom.N` 已存在，resume 仍应可以继续。

## 3. Checkpoint 目录结构

用户通过 `--checkpoint-dir=DIR` 指定目录（不要与 `-o` / `-e` 混用同一目录）：

```
DIR/
  state.sqlite              # 元数据与进度（WAL 模式）
  blobs/
    stringpool              # 进入切片后的 pool 快照（pool 非空时才有）
    geom.0 .. geom.N-1      # 下一 zoom 的输入分片（N = TEMP_FILES = min((MAX_FILES-10)/2, CPUS*4)）
    shared_nodes            # 启用 shared borders 且 nodepos > 0 时
    shared_nodes.bloom
    pool_off.bin            # 各读入线程在 pool 中的偏移（CPUS 个 long long）
    initial_x.bin           # 各读入线程的初始 x 坐标（CPUS 个 unsigned）
    initial_y.bin           # 各读入线程的初始 y 坐标（CPUS 个 unsigned）
    layermaps.bin           # 图层 id 等切片所需快照（自定义二进制格式）
    skip_children.bin       # 每个 zoom 提交后更新（不存在时视为空集合）
    strategies.bin          # 每个 zoom 提交后更新（不存在时视为空集合）
  staging/                  # 写入临时文件，提交后 rename 到 blobs/
```

### 3.1 SQLite 表（schema v1）

#### `job` 表（单行 `id=1`）

| 列 | 类型 | 说明 |
|----|------|------|
| `id` | INTEGER PRIMARY KEY | 固定为 1 |
| `format_version` | INTEGER | `TIPPECANOE_CHECKPOINT_FORMAT`，当前为 1 |
| `fingerprint` | TEXT | SHA-256 指纹（64 位十六进制） |
| `command_line` | TEXT | 原始命令行（未规范化，用于调试） |
| `output_mode` | TEXT | `mbtiles` / `directory` / `pmtiles` |
| `output_path` | TEXT | 输出路径的绝对路径 |
| `temp_files` | INTEGER | `TEMP_FILES` 值 |
| `cpus` | INTEGER | `CPUS` 值 |
| `created_at` | INTEGER | 创建时间（Unix 时间戳） |
| `updated_at` | INTEGER | 最后更新时间 |

#### `input_file` 表

| 列 | 类型 | 说明 |
|----|------|------|
| `path` | TEXT PRIMARY KEY | 输入文件的绝对路径 |
| `size` | INTEGER | 文件大小（字节） |
| `mtime_sec` | INTEGER | 修改时间（秒） |
| `mtime_nsec` | INTEGER | 修改时间（纳秒） |

#### `tiling_state` 表（单行 `id=1`）

| 列 | 类型 | 说明 |
|----|------|------|
| `id` | INTEGER PRIMARY KEY | 固定为 1 |
| `iz` | INTEGER | 当前 zoom 索引 |
| `minzoom` | INTEGER | 最小 zoom |
| `maxzoom` | INTEGER | 最大 zoom |
| `basezoom` | INTEGER | 基础 zoom |
| `last_completed_zoom` | INTEGER | 最后完成的 zoom（NULL 表示尚未完成任何 zoom） |
| `midx` | INTEGER | 中间 x 坐标 |
| `midy` | INTEGER | 中间 y 坐标 |
| `pool_off` | INTEGER | pool 偏移标志 |
| `initial_x` | INTEGER | 初始 x 标志 |
| `initial_y` | INTEGER | 初始 y 标志 |
| `nodepos` | INTEGER | shared_nodes 大小 |
| `entry_snapshot_done` | INTEGER | 切片入口快照是否已完成（0/1） |

#### `zoom_commit` 表

| 列 | 类型 | 说明 |
|----|------|------|
| `zoom` | INTEGER PRIMARY KEY | zoom 级别 |
| `status` | TEXT | 固定为 `committed` |
| `committed_at` | INTEGER | 提交时间（Unix 时间戳） |
| `geom_total_bytes` | INTEGER | 该 zoom 的 geom 数据总字节数 |
| `generation` | INTEGER | 提交代数（递增计数器） |

## 4. 命令行参数

### 4.1 新增参数

| 参数 | 等价形式 | 说明 |
|------|----------|------|
| `--checkpoint-dir=DIR` | `--checkpoint-dir DIR` | 启用 checkpoint，元数据与 blobs 写入 `DIR` |
| `--resume=DIR` | `--resume DIR` | 从已有 checkpoint 目录续跑；**与 `--checkpoint-dir` 互斥** |
| `--checkpoint-force` | — | 若 `DIR` 中已有作业，清空后重新开始（仅影响 checkpoint 目录，不是 `-f`） |

### 4.2 与现有参数的配合

| 场景 | 要求 |
|------|------|
| 首次跑 + checkpoint | `--checkpoint-dir=DIR` + `-o out.mbtiles` 或 `-e outdir` |
| 续跑 | `--resume=DIR` + **相同** `-o`/`-e` 与 **相同** 切片相关参数（如 `-z`、`-Z`、`-d`、`-q` 等）+ **必须** `-F` / `--allow-existing` |
| 清空输出重来 | 对输出使用 `-f`；对 checkpoint 使用 `--checkpoint-force` |
| 无 checkpoint 参数 | 行为与未加此功能前的 tippecanoe **完全一致** |

### 4.3 输出格式说明

| 输出 | 首次 `--checkpoint-dir` | `--resume` |
|------|-------------------------|------------|
| mbtiles（`-o *.mbtiles`） | 支持 | 支持 |
| 目录（`-e DIR`） | 支持 | 支持 |
| PMTiles（`-o *.pmtiles`） | 可记录指纹 | **不支持**，会报错并提示先用 mbtiles/目录，再按现有流程转 PMTiles |

## 5. 使用教程

### 5.1 首次运行（启用 checkpoint）

```bash
tippecanoe -z14 -Z0 \
  -o /data/out.mbtiles \
  --checkpoint-dir=/data/job-42 \
  /data/in.geojson
```

说明：

- checkpoint 目录可以事先不存在，会自动创建（含 `blobs/` 和 `staging/` 子目录）；
- 若目录里 **已有** 未清除的作业（存在 `state.sqlite` 中的 job 记录），需加 `--checkpoint-force` 或换目录。

### 5.2 中断后续跑

```bash
tippecanoe -z14 -Z0 \
  --resume=/data/job-42 \
  -o /data/out.mbtiles \
  -F \
  /data/in.geojson
```

**注意：**

1. **`-z`、`-Z`、`-d`、`-q` 等影响瓦片的参数必须与首次运行一致**（不要首次无 `-q`、续跑加 `-q`，会导致指纹不一致）。
2. **必须加 `-F`**（`--allow-existing`），否则无法保留已写入的瓦片，程序会报错退出。
3. 输入文件路径仍需传入，用于 fingerprint 校验；有有效 checkpoint 时 **不会** 再读 GeoJSON。

#### 5.2.1 kill -9 后的 mbtiles 清理

进程被 `kill -9` 后，mbtiles 文件可能处于不一致状态（WAL/SHM/JOURNAL 残留、未提交 zoom 的部分瓦片）。resume 前需手动清理：

```bash
# 1. 清理 WAL/SHM/JOURNAL 文件
rm -f /data/out.mbtiles-wal /data/out.mbtiles-shm /data/out.mbtiles-journal

# 2. 切换到 DELETE journal 模式（自动回滚未完成事务）
sqlite3 /data/out.mbtiles "PRAGMA journal_mode=DELETE;"

# 3. 删除未提交 zoom 的瓦片（保留已提交 zoom 的瓦片）
LAST_ZOOM=$(sqlite3 /data/job-42/state.sqlite "SELECT last_completed_zoom FROM tiling_state WHERE id=1;")
sqlite3 /data/out.mbtiles "DELETE FROM map WHERE zoom_level > $LAST_ZOOM;"
sqlite3 /data/out.mbtiles "DELETE FROM images WHERE tile_id NOT IN (SELECT tile_id FROM map);"

# 4. 执行 resume
tippecanoe -z14 -Z0 --resume=/data/job-42 -o /data/out.mbtiles -F /data/in.geojson
```

#### 5.2.2 kill -9 后的目录输出清理

```bash
# 删除未提交 zoom 的 pbf 目录
LAST_ZOOM=$(sqlite3 /data/job-tiles/state.sqlite "SELECT last_completed_zoom FROM tiling_state WHERE id=1;")
for z in $(seq $((LAST_ZOOM + 1)) 14); do
  rm -rf /data/tiles/$z
done

# 执行 resume
tippecanoe -z14 -Z0 --resume=/data/job-tiles -e /data/tiles -F /data/in.geojson
```

### 5.3 清空 checkpoint 后重新开作业

```bash
tippecanoe --checkpoint-dir=/data/job-42 --checkpoint-force \
  -o /data/out.mbtiles -f \
  /data/in.geojson
```

- `-f`：删除或覆盖 **输出** mbtiles；
- `--checkpoint-force`：清空 **checkpoint 目录** 内旧作业（删除 blobs/ 和 staging/ 内容，清空 SQLite 表）。

### 5.4 目录输出示例

```bash
# 首次运行
tippecanoe -z10 -e /data/tiles \
  --checkpoint-dir=/data/job-tiles \
  china.geojson

# 续跑
tippecanoe -z10 -e /data/tiles \
  --resume=/data/job-tiles \
  -F china.geojson
```

### 5.5 投影（CRS）提示

若 GeoJSON 内声明的 CRS 与 tippecanoe 默认不一致（例如 EPSG:4490），日志会有警告。这不影响 checkpoint 机制本身；若需指定投影，加上 `-s` 等参数，且 **首次与续跑须一致**（会进入 fingerprint）。

## 6. 接口说明

### 6.1 命令行接口

#### 输入参数

| 参数 | 类型 | 必需 | 说明 |
|------|------|------|------|
| `--checkpoint-dir=DIR` | 路径 | 否 | 启用 checkpoint，指定工作目录 |
| `--resume=DIR` | 路径 | 否 | 从指定 checkpoint 目录续跑 |
| `--checkpoint-force` | 标志 | 否 | 强制覆盖已有 checkpoint 作业 |

| `-f` / `--force` | 标志 | 否 | 删除已有输出文件 |

#### 退出码

| 退出码 | 常量 | 含义 | checkpoint 相关场景 |
|--------|------|------|---------------------|
| 0 | — | 成功 | 所有 zoom 完成 |
| 100 | `EXIT_INCOMPLETE` | 瓦片不完整 | 部分 zoom 完成，checkpoint 已记录 |
| 101 | `EXIT_ARGS` | 参数错误 | fingerprint 不匹配、`--resume` 未加 `-F`、`--checkpoint-dir` 与 `--resume` 同时使用 |
| 104 | `EXIT_EXISTS` | 文件已存在 | checkpoint 目录已有作业但未加 `--checkpoint-force` |
| 111 | `EXIT_OPEN` | 文件打开失败 | checkpoint blob 文件无法打开 |
| 116 | `EXIT_SQLITE` | SQLite 错误 | checkpoint 数据库操作失败 |

## 7. 行为与退出码

| 情况 | 行为 |
|------|------|
| 切片未跑完所有 zoom | 与原先一致，可能返回 `100`（`EXIT_INCOMPLETE`）；checkpoint 中记录 `last_completed_zoom`，续跑从下一级补 |
| 指纹不一致 | 退出 `101`（`EXIT_ARGS`），打印 stored / expected 指纹 |
| 续跑未加 `-F` | 退出 `101`（`EXIT_ARGS`），提示 `--resume requires -F` |
| 同时指定 `--checkpoint-dir` 与 `--resume` | 退出 `101`（`EXIT_ARGS`），提示两者不能同时使用 |
| checkpoint 目录已有作业但未加 `--checkpoint-force` | 退出 `104`（`EXIT_EXISTS`），提示使用 `--checkpoint-force` |
| PMTiles 输出 + `--resume` | 退出 `101`（`EXIT_ARGS`），提示改用 mbtiles 或目录 |
| 读入阶段中断且无 entry snapshot | `--resume` 无法跳过读入，相当于无切片 checkpoint，需全量重跑 |

续跑完成后若输出里已有 metadata，可能出现 `UNIQUE constraint failed: metadata.name` 等提示，一般可忽略（正在更新已有 tileset 的元数据）。

## 8. 故障排查

| 现象 | 可能原因 | 处理 |
|------|----------|------|
| `checkpoint fingerprint mismatch` | 续跑时 `-z`、输入文件或输出路径与首次不同 | 使用与首次完全相同的切片参数与输入；检查是否多了 `-q` |
| `checkpoint directory already has a job` | 目录里已有作业 | `--checkpoint-force` 或换新 `--checkpoint-dir` |
| `--resume requires -F` | 未保留已有瓦片 | 加上 `-F` |
| `--resume is not supported for PMTiles` | 输出为 PMTiles | 改用 mbtiles 或 `-e` 目录 |
| `wrong length decoding feature` | blobs/ 中存在过期 geom 数据 | 确保使用最新代码（已修复 geom 原子替换逻辑） |
| `ANALYZE failed: disk I/O error` 或 `database is locked` | kill -9 后 mbtiles WAL/SHM 残留 | 手动清理 WAL/SHM/JOURNAL，切换到 DELETE 模式（见 5.2.1 节） |
| `UNIQUE constraint failed` | resume 时 mbtiles 中已有未提交 zoom 的瓦片 | 手动删除未提交 zoom 的瓦片（见 5.2.1 节） |
| 续跑很快结束、瓦片未增加 | 首次已跑完全部 zoom | 正常；检查 `last_completed_zoom` 是否已达 `maxzoom` |
| resume 后输出 0 个瓦片 | 旧版本 `copy_fd_to_file` 的 fd 偏移量 bug | 确保使用已修复该 bug 的版本 |

查看进度示例：

# 查看作业指纹和命令行

## 9. 注意事项与限制条件

### 9.1 当前限制

- 仅 **原生** `main.cpp` / `tile.cpp` 路径，不含 `tippecanoe-db`；
- **读入过程**无增量 checkpoint（阶段 A 中断需全量重跑）；
- checkpoint 磁盘占用约为 **stringpool + geom 分片** 量级，请把 `--checkpoint-dir` 放在空间充足的磁盘；
- **kill -9 后需手动清理**：mbtiles 模式需清理 WAL/SHM/JOURNAL 和未提交 zoom 的瓦片；目录模式需删除未提交 zoom 的 pbf 目录；
- 不支持 `--checkpoint-prune`（成功后自动删 blobs）、`--checkpoint-trust-output`（从输出反推进度）等专家选项；
- **`--resume` 时参数必须完全一致**：包括 `-q`、`-d` 等所有影响瓦片内容的参数，否则 fingerprint 不匹配；
- **PMTiles 不支持 resume**：PMTiles 格式的追加写入机制与 checkpoint 不兼容。

### 9.2 安全性保证

- **原子提交**：`on_zoom_complete` 使用 staging → rename → SQLite 事务的三步原子提交，保证 `kill -9` 后 `blobs/` 中始终存在有效的完整版本；
- **fd 偏移量保护**：`copy_fd_to_file` 保存并恢复传入 fd 的偏移量，不影响后续读取；
- **容错读取**：`skip_children.bin` 和 `strategies.bin` 不存在时视为空集合，而非报错退出；
- **指纹校验**：SHA-256 指纹确保续跑时参数和输入文件一致，防止数据损坏。

### 9.3 后续可能增加

- 读入阶段按文件/块增量 checkpoint；
- PMTiles 可续写或完成后一键转换；
- `tippecanoe-db` 共用 checkpoint 库；
- `SIGTERM` 时优雅提交当前 zoom；
- resume 时自动清理 mbtiles 中未提交 zoom 的瓦片；
- resume 时自动处理 WAL/SHM/JOURNAL 残留；
- `--checkpoint-prune` 等维护命令。
