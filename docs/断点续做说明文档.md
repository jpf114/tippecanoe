# Tippecanoe 断点续做（Checkpoint / Resume）

本文档说明原生 `tippecanoe`（GeoJSON / CSV / FlatGeobuf 等读入路径）的 **zoom 级断点续做** 功能。
**不包含** `tippecanoe-db`（PostGIS / Mongo 等），后者在后续版本中再考虑。

> **重要**：本文档描述的是 **自包含 resume（self-contained resume）** 设计。
> 续跑时只需 `--resume=DIR` 一个参数，所有必要的输出路径、zoom 范围、输入文件列表均从 checkpoint 目录自动恢复，无需在命令行重复传入。

---

## 1. 功能概述

在生成矢量瓦片时，任务往往耗时很长（读入大 GeoJSON、多级 zoom 切片）。进程被 `kill -9`、OOM 或机器重启打断后，传统做法只能从头重跑。

断点续做提供：

- **专用 checkpoint 工作目录**（与 `-o` / `-e` 输出路径分开）；
- **每个 zoom 成功结束后** 落盘中间状态；
- **自包含 `--resume=DIR`** 时跳过读入与 radix，从「上一完成 zoom 的下一级」继续切片；
- **自动清理 kill -9 残留**：WAL/SHM/JOURNAL 文件、未提交 zoom 的瓦片、未提交 zoom 的目录；
- **自动恢复 metadata**：`bounds` / `center` / `antimeridian_adjusted_bounds` / `vector_layers` / `tilestats` 与正常路径完全一致。

### 1.1 两阶段模型（必读）

| 阶段 | 内容 | 是否 checkpoint |
|------|------|-----------------|
| **阶段 A** | 读入 GeoJSON、radix 排序、合并 stringpool、建 shared_nodes 等 | **否** |
| **阶段 B** | `traverse_zooms`：按 zoom 写 mbtiles 或目录瓦片 | **是**（每 zoom 一次） |

因此：

- 中断发生在 **读入 / 排序** 时：checkpoint 目录里通常还没有可用的「切片入口快照」，下次只能 **全量重跑**（与计划一致）。
- 中断发生在 **切片过程中**：已完成的 zoom 有记录，且已保存进入下一 zoom 所需的 geom 分片与 stringpool，可 **`--resume` 续跑**。

「zoom 级」**不是**「只记录 mbtiles 里已有哪些 z」，而是必须保存 **算法中间态**（否则无法从 z+1 继续，因为 z+1 的输入来自 z 结束时生成的 geom 分片，且属性索引依赖同一次读入的 stringpool）。

## 2. 设计原理

### 2.1 核心架构：SQLite 账本 + 文件系统仓库

| 内容 | 存储位置 | 原因 |
|------|----------|------|
| 作业指纹、命令行、zoom 进度、时间戳 | `state.sqlite` | 便于事务、查询、原子更新 |
| stringpool、geom 分片、shared_nodes、bloom、file_bbox | `blobs/` 下普通文件 | 可达 GB 级；SQLite BLOB 性能差、单文件易膨胀 |
| 写入中的数据 | `staging/` | 写完后 `rename` 到 `blobs/`，再更新 SQLite |

SQLite 充当 **作业账本**；文件系统充当 **中间态仓库**。

**技术选型依据**：

- **SQLite（WAL 模式）**：元数据量小（KB 级），需要事务保证（fingerprint + zoom_commit 的原子性），WAL 模式支持并发读取；
- **文件系统（blobs/）**：中间态数据量大（GB 级），使用 `mmap` 直接映射到进程地址空间，避免额外的序列化/反序列化开销；
- **staging → blobs 原子提交**：`rename()` 在同一文件系统上是原子操作，保证 `kill -9` 后 `blobs/` 中始终存在有效的完整版本。

### 2.2 原子提交顺序（防止半截状态）

每个 zoom 的 `commit` 顺序为：

1. 将新的 geom 分片（`geom.{slot}.g{gen}`）、`skip_children`、`strategies` 写入 `staging/`；
2. 对相关文件 `fsync`；
3. **原子 `rename`** `staging/` → `blobs/`：
   - 有新数据的文件：`rename()` 原子替换旧版本；
   - 无新数据的 slot：不写文件（该 slot 的旧 gen 文件稍后清理）；
4. 清理旧代数（old generation）的 geom 文件；
5. SQLite 事务：写入 `zoom_commit`，更新 `tiling_state.last_completed_zoom` 等。

**关键设计**：步骤 3 中 **不先删除旧 blob 再 rename**，而是直接 `rename` 覆盖。若先删后写，在 `kill -9` 后 `blobs/` 中可能为空，导致 resume 失败。`rename()` 原子替换保证 `blobs/` 中始终存在有效版本。

仅在当前 zoom 的 drop 多 pass 循环 **全部成功**（`again == false`）且 `err == INT_MAX` 时调用 `on_zoom_complete`，避免「重试中」的错误进度。

### 2.3 文件代数（generation）机制

geom 分片文件使用 **代数后缀** 命名，避免 rename 覆盖旧文件时的竞态问题：

| 文件名 | 含义 |
|--------|------|
| `geom.initial` | 初始快照（阶段 A 完成后写入一次，未压缩） |
| `geom.{slot}.g{gen}` | 第 `gen` 代、第 `slot` 个分片（每个 zoom 完成后写入，压缩格式） |

- `slot` 范围：`0 .. TEMP_FILES-1`（`TEMP_FILES = min((MAX_FILES-10)/2, CPUS*4)`）；
- `gen` 是递增计数器，每次 `on_zoom_complete` 时 `+1`；
- resume 时从 `zoom_commit` 表读取 `MAX(generation)`，加载对应代数的所有 geom 文件；
- 旧代数文件在新代数文件安全 rename 到 `blobs/` 后才被清理。

### 2.4 与切片算法的关系

- **不修改** `write_tile`、drop/coalesce、几何切分、radix 等核心逻辑；
- 仅在 `traverse_zooms` 循环末尾增加 **一处** 钩子，具体逻辑在 `checkpoint.cpp`；
- `main.cpp` 的 `read_input` 首尾负责「是否跳过读入」与 `snapshot_tiling_entry`。

### 2.5 作业指纹（fingerprint）

指纹是一个 **SHA-256 哈希值**，存储在 `state.sqlite` 的 `job.fingerprint` 列。

#### 2.5.1 指纹的用途

**重要**：指纹仅用于校验 **checkpoint 数据库的内部一致性**，**不校验** resume 命令行参数。

续跑时，`verify_fingerprint_internal()` 的行为：

1. 从 `job` 表读取 `normalized_cmd`、`output_mode`、`output_path`、`temp_files`、`cpus`；
2. 从 `input_file` 表读取所有输入文件的 `path`、`size`、`mtime_sec`、`mtime_nsec`；
3. 用这些 **存储的值** 重新计算指纹；
4. 与 `job.fingerprint` 中存储的值比较。

由于步骤 1-2 使用的全是 DB 中存储的值（而非当前命令行或磁盘上文件的 stat），因此这个校验确保的是「checkpoint 数据库没有被外部篡改或损坏」，而不是「当前 resume 命令行与首次运行一致」。

#### 2.5.2 参与哈希的内容

- 格式版本 `TIPPECANOE_CHECKPOINT_FORMAT`（当前为 `1`）；
- **规范化后的命令行**（已剔除 `--checkpoint-dir`、`--resume`、`--checkpoint-force`、`-F`、`-f` 等标志）；
- 输出模式（`mbtiles` / `directory` / `pmtiles`）与 **输出路径绝对路径**；
- `TEMP_FILES`、`CPUS`；
- `prevent[]` / `additional[]` 标志位；
- 输入文件列表：`绝对路径 + size + mtime`（排序后）。

#### 2.5.3 命令行规范化规则

| 标志 | 处理方式 | 说明 |
|------|----------|------|
| `--checkpoint-dir=DIR` | 整体移除 | 等号形式，标志含参数 |
| `--checkpoint-dir DIR` | 标志和参数均移除 | 空格形式，需跳过下一个 token |
| `--resume=DIR` | 整体移除 | 等号形式 |
| `--resume DIR` | 标志和参数均移除 | 空格形式 |
| `--checkpoint-force` | 移除 | 无参数标志 |
| `-F` / `--allow-existing` | 移除 | 无参数标志 |
| `-f` / `--force` | 移除 | 无参数标志 |

#### 2.5.4 指纹不匹配的后果

指纹不匹配（仅当 checkpoint 数据库被外部篡改或损坏时才会发生）会以退出码 `101`（`EXIT_ARGS`）失败并打印 stored / expected 指纹。

### 2.6 关键算法逻辑

#### 2.6.1 `copy_fd_to_file` — fd 到文件的安全拷贝

`on_zoom_complete` 需要将 `geomfd[j]` 的内容拷贝到 `blobs/geom.{slot}.g{gen}`。由于 `geomfd[j]` 同时被 `traverse_zooms` 后续代码使用（`fdopen(geomfd[j], "rb")` 读取），拷贝过程必须 **保存并恢复文件偏移量**：

```
saved_pos = lseek(fd, SEEK_CUR)     // 保存当前偏移量
lseek(fd, 0, SEEK_SET)              // 回到文件头
read(fd, ...) → write(dest, ...)   // 拷贝数据
lseek(fd, saved_pos, SEEK_SET)      // 恢复原始偏移量
```

若不恢复偏移量，`read()` 会将 fd 偏移量推到文件末尾，导致后续 `fdopen()` 读不到任何数据。

#### 2.6.2 `compressed` 标志的正确计算

在 `traverse_zooms` 中，z0 的数据是未压缩的（排序和 maxzoom 修正需要操作原始数据），z1+ 的数据是压缩的。resume 时从 `last_completed_zoom + 1` 开始，该 zoom 的输入来自上一级 `on_zoom_complete` 保存的压缩数据，因此：

```
compressed = (z > 0)    // z0 未压缩，z1+ 均为压缩
```

注意：不能使用 `compressed = (z != iz)`，因为当 `iz > 0`（resume 起始 zoom）时，`z == iz` 会导致 `compressed = false`，从而错误地按未压缩格式读取压缩数据。

#### 2.6.3 `skip_children` / `strategies` 的容错读取

`read_skip_children_blob` 和 `read_strategies_blob` 在文件不存在时 **优雅返回**（空集合），而非 `exit(EXIT_OPEN)`。原因：若进程在第一个 zoom 完成前被 `kill -9`，`blobs/` 中尚无这两个文件，但 `stringpool` 和 `geom.initial` 已存在，resume 仍应可以继续。

#### 2.6.4 `file_bbox` 持久化与 metadata 重建

为使 resume 后的 `metadata.bounds` / `antimeridian_adjusted_bounds` 与正常路径完全一致，checkpoint 持久化了三个 z=32 像素坐标的全局 bbox：

| 文件 | 含义 | 默认值 |
|------|------|--------|
| `file_bbox.bin` | 数据的全局 bbox（z=32 像素坐标） | `{UINT_MAX, UINT_MAX, 0, 0}` |
| `file_bbox1.bin` | 标准 -180~180 世界面的 bbox | `{0xFFFFFFFF, 0xFFFFFFFF, 0, 0}` |
| `file_bbox2.bin` | 0~360 世界面的 bbox（用于跨日期线检测） | `{0x1FFFFFFFF, 0xFFFFFFFF, 0x100000000, 0}` |

resume 时 `restore_tiling()` 读取这三个文件，`main.cpp` 的 resume 路径用它们通过 `tile2lonlat(z=32)` 重建经纬度 bbox，逻辑与正常路径（`main.cpp` 行 2851-2891）完全一致。

#### 2.6.5 `layermaps.bin` 格式 v3

为使 resume 后的 `metadata.json`（`vector_layers` + `tilestats`）与正常路径完全一致，layermaps blob 格式已升级到 v3：

| 版本 | 字段布局 |
|------|----------|
| v1 | `segs, [layers, [(nlen, name, id, minz, maxz)]]` |
| v2 | v1 + `points, lines, polygons, retain` |
| **v3** | v2 + `description` + 完整 `tilestats`（含 `min`/`max`/`type`/`sample_values`） |

v3 格式使 resume 路径能够完整重建 `layermap_entry` 的所有字段，从而生成与正常路径字节级一致的 `vector_layers` 和 `tilestats` JSON。

**版本兼容性**：若 `layermaps.bin` 的版本号不等于 3（例如旧版本生成的 v1/v2 文件），`read_layermaps_blob` 会打印警告并返回空 layermaps。此时瓦片内容不受影响，但 `metadata.vector_layers` 和 `metadata.tilestats` 会为空。建议使用 v3 兼容的二进制从 scratch 重跑以获得完整 metadata。

#### 2.6.6 `cleanup_resume_wal` 的热日志回滚流程

进程被 `kill -9` 后，mbtiles 文件可能处于不一致状态：WAL/SHM 文件残留、可能存在热日志（hot journal，记录未完成的事务）。

**正确的清理顺序**（`cleanup_resume_wal` 实现）：

1. **删除 WAL/SHM 文件**：`unlink(*-wal)`、`unlink(*-shm)`；
2. **重置 DB header**：若文件偏移 18-19 处的 magic 为 `0x02 0x00`（WAL 模式），改为 `0x01 0x00`（DELETE 模式）；
3. **打开数据库回滚热日志**：`sqlite3_open()` + `busy_timeout(30s)` + `PRAGMA journal_mode=DELETE`；SQLite 会自动检测并回滚热日志中的未完成事务；
4. **关闭数据库**；
5. **删除 -journal 文件**：回滚完成后，热日志应已被 SQLite 自动清理；`unlink(*-journal)` 清除任何残留。

**关键**：步骤 1 中 **不能** 先删除 `-journal` 文件。若先删 journal，SQLite 打开数据库时无法回滚未完成事务，后续 `PRAGMA` 执行会报 `database is locked`（退出码 116）。必须先让 SQLite 回滚，再清理 journal。

## 3. Checkpoint 目录结构

用户通过 `--checkpoint-dir=DIR` 指定目录（不要与 `-o` / `-e` 混用同一目录）：

```
DIR/
  state.sqlite              # 元数据与进度（WAL 模式）
  blobs/
    stringpool              # 进入切片后的 pool 快照（pool 非空时才有）
    geom.initial            # 初始快照（阶段 A 完成后写入，未压缩）
    geom.0.g1               # 第 1 代、slot 0 的 geom 分片（z=iz 完成后写入）
    geom.1.g1               # 第 1 代、slot 1 的 geom 分片
    ...
    geom.{slot}.g{gen}      # 第 gen 代、slot N 的 geom 分片
    shared_nodes            # 启用 shared borders 且 nodepos > 0 时
    shared_nodes.bloom
    pool_off.bin            # 各读入线程在 pool 中的偏移（CPUS 个 long long）
    initial_x.bin           # 各读入线程的初始 x 坐标（CPUS 个 unsigned）
    initial_y.bin           # 各读入线程的初始 y 坐标（CPUS 个 unsigned）
    layermaps.bin           # 图层快照（v3 格式，含 tilestats）
    skip_children.bin       # 每个 zoom 提交后更新（不存在时视为空集合）
    strategies.bin          # 每个 zoom 提交后更新（不存在时视为空集合）
    file_bbox.bin           # 数据全局 bbox（z=32 像素坐标，4 个 long long）
    file_bbox1.bin          # -180~180 世界面 bbox（4 个 long long）
    file_bbox2.bin          # 0~360 世界面 bbox（4 个 long long）
  staging/                  # 写入临时文件，提交后 rename 到 blobs/
```

**geom 文件命名规则**：

- `geom.initial`：阶段 A 完成后的初始快照，未压缩，仅 1 个文件（slot 0）；
- `geom.{slot}.g{gen}`：每个 zoom 完成后写入，压缩格式，`slot` 范围 `0..TEMP_FILES-1`，`gen` 递增；
- 当 `last_completed_zoom < 0`（无 zoom 完成）时，resume 加载 `geom.initial`；
- 当 `last_completed_zoom >= 0` 时，resume 加载 `MAX(generation)` 对应的所有 `geom.{slot}.g{gen}`，并清理 `geom.initial` 和旧代数文件。

## 4. 命令行参数

### 4.1 新增参数

| 参数 | 等价形式 | 说明 |
|------|----------|------|
| `--checkpoint-dir=DIR` | `--checkpoint-dir DIR` | 启用 checkpoint，元数据与 blobs 写入 `DIR` |
| `--resume=DIR` | `--resume DIR` | 从已有 checkpoint 目录续跑；**自包含**，无需其他参数 |
| `--checkpoint-force` | — | 若 `DIR` 中已有作业，清空后重新开始（仅影响 checkpoint 目录，不是 `-f`） |

### 4.2 自包含 resume 行为

`--resume=DIR` 是 **自包含的**：所有续跑所需的信息都从 checkpoint 目录的 `state.sqlite` 读取，命令行无需（也不应该）传入 `-o`、`-e`、`-z`、`-Z`、`-F`、输入文件等参数。

| 命令行参数 | resume 时的处理 |
|------------|-----------------|
| `-o out.mbtiles` | 打印 `note: ignoring -o/-e with --resume (using stored output path)`，忽略；使用 checkpoint 中存储的 `output_path` |
| `-e outdir` | 同上 |
| `-z` / `-Z` / `-d` / `-q` 等 | 忽略；使用 checkpoint 中存储的 `maxzoom` / `minzoom` |
| 输入文件路径 | 忽略；使用 checkpoint 中 `input_file` 表存储的路径列表 |
| `-F` / `--allow-existing` | 自动等价启用（`forcetable = 1`），无需手动传入 |
| `-f` / `--force` | 打印 `warning: ignoring -f with --resume (tiles must be preserved)`，忽略；resume 必须保留已写入的瓦片 |

### 4.3 使用场景

| 场景 | 命令 |
|------|------|
| 首次跑 + checkpoint | `tippecanoe -z14 -o out.mbtiles --checkpoint-dir=DIR input.geojson` |
| 续跑（自包含） | `tippecanoe --resume=DIR` |
| 清空 checkpoint 重来 | `tippecanoe --checkpoint-dir=DIR --checkpoint-force -o out.mbtiles -f input.geojson` |
| 无 checkpoint 参数 | 行为与未加此功能前的 tippecanoe **完全一致** |

### 4.4 输出格式说明

| 输出 | 首次 `--checkpoint-dir` | `--resume` |
|------|-------------------------|------------|
| mbtiles（`-o *.mbtiles`） | 支持 | 支持 |
| 目录（`-e DIR`） | 支持 | 支持 |
| PMTiles（`-o *.pmtiles`） | 可记录指纹 | **不支持**，会报错并提示先用 mbtiles/目录，再按现有流程转 PMTiles |

## 5. 使用教程

### 5.1 首次运行（启用 checkpoint）

```bash
tippecanoe -z14 -Z0 \
  -o /data/out.mbtiles \
  --checkpoint-dir=/data/job-42 \
  /data/in.geojson
```

说明：

- checkpoint 目录可以事先不存在，会自动创建（含 `blobs/` 和 `staging/` 子目录）；
- 若目录里 **已有** 未清除的作业（存在 `state.sqlite` 中的 job 记录），需加 `--checkpoint-force` 或换目录。

### 5.2 中断后续跑（自包含 resume）

```bash
# 只需一个参数：--resume 指向 checkpoint 目录
tippecanoe --resume=/data/job-42
```

程序会自动：

1. 从 `state.sqlite` 读取原始命令、输出路径、zoom 范围、输入文件列表；
2. 打印 resume 摘要（原始命令、输出路径、输入文件、zoom 范围、续跑起始 zoom）；
3. 忽略命令行上的 `-o` / `-e` / `-z` / `-Z` / `-f` 等参数（如有）；
4. 自动设置 `forcetable = 1`（等价于 `-F`）；
5. 清理 kill -9 残留（WAL/SHM/JOURNAL、未提交 zoom 的瓦片/目录）；
6. 校验 checkpoint 内部一致性（fingerprint）；
7. 从 `last_completed_zoom + 1` 继续切片；
8. 完成后重建 metadata（`bounds` / `center` / `vector_layers` / `tilestats` 等，与正常路径完全一致）。

**resume 摘要输出示例**：

```
=== Resuming from checkpoint: /data/job-42 ===
  Original command: tippecanoe -z14 -Z0 -o /data/out.mbtiles --checkpoint-dir=/data/job-42 /data/in.geojson
  Output: /data/out.mbtiles (mbtiles)
  Input: /data/in.geojson
  Zoom range: 0-14
  Resuming from zoom 8 (last completed: 7)
========================================
```

### 5.3 kill -9 后的自动清理

进程被 `kill -9` 后，resume 会 **自动** 执行以下清理（无需手动干预）：

#### 5.3.1 mbtiles 模式

1. **`cleanup_resume_wal(output_path)`**（在打开输出 DB 之前调用）：
   - 删除 `*-wal`、`*-shm` 文件；
   - 重置 DB header 的 WAL magic 为 DELETE 模式；
   - `sqlite3_open` + `PRAGMA journal_mode=DELETE` 回滚热日志中的未完成事务；
   - 删除 `*-journal` 文件。

2. **`cleanup_resume_tiles(outdb, last_completed_zoom)`**（在打开输出 DB 之后调用）：
   - `DELETE FROM map WHERE zoom_level > last_completed_zoom`（删除未提交 zoom 的瓦片）；
   - `DELETE FROM images WHERE tile_id NOT IN (SELECT tile_id FROM map)`（删除孤立 images）。

#### 5.3.2 目录模式

**`cleanup_resume_dirs(output_path, last_completed_zoom, maxzoom)`**：
- 对 `z = last_completed_zoom + 1 .. maxzoom`，`rm -rf` 对应的 zoom 目录。

### 5.4 清空 checkpoint 后重新开作业

```bash
tippecanoe --checkpoint-dir=/data/job-42 --checkpoint-force \
  -o /data/out.mbtiles -f \
  /data/in.geojson
```

- `-f`：删除或覆盖 **输出** mbtiles；
- `--checkpoint-force`：清空 **checkpoint 目录** 内旧作业（删除 blobs/ 和 staging/ 内容，清空 SQLite 表）。

### 5.5 目录输出示例

```bash
# 首次运行
tippecanoe -z10 -e /data/tiles \
  --checkpoint-dir=/data/job-tiles \
  china.geojson

# 续跑（自包含）
tippecanoe --resume=/data/job-tiles
```

### 5.6 投影（CRS）提示

若 GeoJSON 内声明的 CRS 与 tippecanoe 默认不一致（例如 EPSG:4490），日志会有警告。这不影响 checkpoint 机制本身；若需指定投影，加上 `-s` 等参数。由于 resume 是自包含的，首次与续跑的投影参数自然一致（都从 checkpoint 读取）。

## 7. 行为与退出码

| 情况 | 行为 |
|------|------|
| 切片未跑完所有 zoom | 与原先一致，可能返回 `100`（`EXIT_INCOMPLETE`）；checkpoint 中记录 `last_completed_zoom`，续跑从下一级补 |
| checkpoint DB 内部不一致（fingerprint 不匹配） | 退出 `101`（`EXIT_ARGS`），打印 stored / expected 指纹 |
| `--resume` 但 checkpoint 无 entry snapshot | 退出 `101`（`EXIT_ARGS`），提示「initial snapshot not saved, please re-run from scratch」 |
| 同时指定 `--checkpoint-dir` 与 `--resume` | 退出 `101`（`EXIT_ARGS`），提示两者不能同时使用 |
| checkpoint 目录已有作业但未加 `--checkpoint-force` | 退出 `104`（`EXIT_EXISTS`），提示使用 `--checkpoint-force` |
| PMTiles 输出 + `--resume` | 退出 `101`（`EXIT_ARGS`），提示改用 mbtiles 或目录 |
| 读入阶段中断且无 entry snapshot | `--resume` 退出 `101`，提示从 scratch 重跑 |
| `--resume` 时命令行有 `-o` / `-e` | 打印 `note: ignoring -o/-e`，使用存储的 output_path |
| `--resume` 时命令行有 `-f` | 打印 `warning: ignoring -f`，强制保留已写入瓦片 |
| `--resume` 时无输入文件参数 | 自动从 `input_file` 表读取输入文件列表 |
| kill -9 后 `--resume` | 自动清理 WAL/SHM/JOURNAL、回滚热日志、删除未提交 zoom 的瓦片/目录 |

## 8. 故障排查

| 现象 | 可能原因 | 处理 |
|------|----------|------|
| `checkpoint fingerprint mismatch` | checkpoint 数据库被外部篡改或损坏 | 检查 `state.sqlite` 是否被手动修改；若损坏严重，用 `--checkpoint-force` 从 scratch 重跑 |
| `checkpoint directory already has a job` | 目录里已有作业 | `--checkpoint-force` 或换新 `--checkpoint-dir` |
| `checkpoint is incomplete (initial snapshot not saved)` | 进程在读入阶段被 kill，未进入切片阶段 | 从 scratch 重跑（不加 `--resume`） |
| `--resume is not supported for PMTiles` | 输出为 PMTiles | 改用 mbtiles 或 `-e` 目录 |
| `wrong length decoding feature` | blobs/ 中存在过期 geom 数据 | 确保使用最新代码（已修复 geom 原子替换逻辑） |
| `database is locked` (exit 116) | kill -9 后热日志未回滚 | 已在 `cleanup_resume_wal` 中自动处理；若仍出现，确保使用最新代码 |
| `UNIQUE constraint failed` | resume 时 mbtiles 中有未提交 zoom 的瓦片 | 已在 `cleanup_resume_tiles` 中自动处理；若仍出现，手动删除未提交 zoom 的瓦片 |
| 续跑很快结束、瓦片未增加 | 首次已跑完全部 zoom | 正常；检查 `last_completed_zoom` 是否已达 `maxzoom` |
| resume 后输出 0 个瓦片 | 旧版本 `copy_fd_to_file` 的 fd 偏移量 bug | 确保使用已修复该 bug 的版本 |
| resume 后 metadata.bounds 不正确 | 旧版本未持久化 `file_bbox` | 确保使用已修复该问题的版本（v3 layermaps + file_bbox.bin） |
| resume 后 vector_layers / tilestats 为空 | 旧版本 layermaps 格式（v1/v2）不含 tilestats | 确保使用 v3 格式；旧 checkpoint 需从 scratch 重跑 |

## 9. 注意事项与限制条件

### 9.1 当前限制

- 仅 **原生** `main.cpp` / `tile.cpp` 路径，不含 `tippecanoe-db`；
- **读入过程**无增量 checkpoint（阶段 A 中断需全量重跑）；
- checkpoint 磁盘占用约为 **stringpool + geom 分片** 量级，请把 `--checkpoint-dir` 放在空间充足的磁盘；
- **PMTiles 不支持 resume**：PMTiles 格式的追加写入机制与 checkpoint 不兼容；
- `--resume` 时命令行传入的 `-z`、`-Z`、`-d`、`-q`、输入文件等参数均被忽略（使用 checkpoint 中存储的值）；
- 旧版本（v1/v2）的 `layermaps.bin` 与 v3 不兼容，resume 后 `vector_layers` / `tilestats` 会为空（瓦片内容不受影响）。

### 9.2 安全性保证

- **原子提交**：`on_zoom_complete` 使用 staging → rename → SQLite 事务的三步原子提交，保证 `kill -9` 后 `blobs/` 中始终存在有效的完整版本；
- **fd 偏移量保护**：`copy_fd_to_file` 保存并恢复传入 fd 的偏移量，不影响后续读取；
- **容错读取**：`skip_children.bin` 和 `strategies.bin` 不存在时视为空集合，而非报错退出；
- **内部一致性校验**：SHA-256 指纹确保 checkpoint 数据库未被外部篡改或损坏；
- **自动清理**：resume 时自动清理 kill -9 残留（WAL/SHM/JOURNAL、未提交瓦片、未提交目录），无需手动干预；
- **热日志回滚**：`cleanup_resume_wal` 先让 SQLite 回滚热日志，再删除 journal 文件，确保数据库一致性；
- **metadata 一致性**：`file_bbox` 持久化 + `layermaps` v3 确保 resume 后的 `bounds` / `center` / `vector_layers` / `tilestats` 与正常路径完全一致。

### 9.3 已修复的历史问题

| 问题 | 原因 | 修复方式 |
|------|------|----------|
| resume 后 `metadata.bounds` 不正确 | resume 路径未恢复 `file_bbox`，使用默认值计算 bounds | 持久化 `file_bbox.bin` / `file_bbox1.bin` / `file_bbox2.bin`，resume 时恢复并重建 bbox |
| resume 后 `vector_layers` / `tilestats` 为空 | `layermaps.bin` v1/v2 格式不含 `description` 和 `tilestats` 字段 | 升级到 v3 格式，序列化完整的 `layermap_entry`（含 `points` / `lines` / `polygons` / `retain` / `description` / `tilestats`） |
| `database is locked` (exit 116) | `cleanup_resume_wal` 先删除 `-journal` 文件，导致 SQLite 无法回滚热日志 | 调整顺序：先删 WAL/SHM → 重置 DB header → sqlite3_open 回滚热日志 → 最后删 journal |
| `make checkpoint-test` 失败 | 旧测试用例与自包含 resume 行为不匹配；瓦片数期望值错误 | 重写 `checkpoint-test` 目标，测试自包含 resume + metadata diff + kill -9 自动清理 |

### 9.4 后续可能增加

- 读入阶段按文件/块增量 checkpoint；
- PMTiles 可续写或完成后一键转换；
- `tippecanoe-db` 共用 checkpoint 库；
- `SIGTERM` 时优雅提交当前 zoom；
- `--checkpoint-prune` 等维护命令。
